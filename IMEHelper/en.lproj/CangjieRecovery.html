Recover saved Cangjie characters

“Saved unavailable” means the list could not be read, not that it is empty. IMEHelper preserves the file and disables saving after a read failure. This help page is stored locally and requires no internet connection.

Preserve your data first

  1. Quit every IMEHelper process. Run only one IMEHelper at a time in the same macOS account, including copies of the same version. Concurrent saves are not protected against overwriting another process’s changes.
  2. In Finder, choose Go → Go to Folder and enter ~/Library/Application Support/IMEHelper/.
  3. Copy cangjie-list.json to another folder as a backup before checking the original. Do not delete it or replace it with an empty file.

Check the cause

  • If a newer IMEHelper created the file, use a version that supports that format. Do not lower the format version by hand to bypass validation.
  • Check that your account can read and write both the file and its folder. If you have a working backup, restore it after quitting IMEHelper; keep the failing file for comparison.
  • If you edited the JSON, check its syntax and fields. Duplicate record identifiers, duplicate raw characters, invalid codes, or inconsistent legacy text are rejected. If you are unsure, keep the backup and seek help instead of guessing changes.
  • Search Console for [CangjieLookup] and inspect the fixed reason value: for example storeMalformed, storeDuplicateIdentifier, storeDuplicateCharacter, storeInvalidCharacter, storeInvalidCode, storeInvalidDate, storeLegacyTextMismatch, storeReadFailed, or unsupportedVersion. Diagnostics do not include saved text or file contents.

After checking the file, start one IMEHelper and open Cangjie Lookup. If the app is still running, choose Retry after repairing the file. The count and saving controls return only after the list loads successfully.

Legacy lists

Legacy lists containing whole passages are converted to individual characters when read. Reading alone does not change the file. The first successful save or deletion writes the new character-based format without preserving passage grouping or creating an automatic backup. Back up the old file first if you need those groups.
